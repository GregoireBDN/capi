# Threat model

- **Issue**: #102 (milestone M7 Access & security)
- **Date**: 2026-11-14, on `main` at `5abde73` (after #170, wallet sync)
- **Companions**: [ASVS 4.0 level 2 checklist](asvs-l2-checklist.md), [audit report](audit-2026-11-14.md)

Finances is a single-user, self-hosted personal finance tracker. One owner, one account, no public sign-up. It runs on one VPS reachable only through the owner's tailnet (ADR 0001) and is used mostly from an iPhone as a PWA, plus a local MCP server for Claude.

## 1. Assets

| Asset                                                                                                                  | Where it lives                                                                                                          | Why it matters                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Financial data**: transactions (labels, amounts, dates), balances, budgets, notes, net worth, crypto holdings        | Postgres `db_data` volume; API responses; the browser while a page is open                                              | The whole point of the app. Confidentiality first (it maps the owner's life, income and habits), then integrity. |
| **Wallet public keys** (xpub / ypub / zpub, EVM addresses)                                                             | `crypto_wallet_keys`; sent to Esplora / JSON-RPC only when wallet sync is on (ADR 0002)                                 | Not spending keys, but an xpub reveals every address, past and future, hence the wallet's history and balance.   |
| **Session**: `token` (15 min access JWT) and `refresh_token` (30 days, rotating) cookies                               | Browser cookie jar (httpOnly); `refresh_tokens` table (SHA-256 hashes)                                                  | Whoever holds them reads and edits everything except the session-only routes that need a fresh sign-in.          |
| **Credentials**: password hash (bcrypt), passkeys (public keys), password reset and email tokens (hashed)              | `users`, `webauthn_credentials`, `password_reset_tokens`, `email_verification_tokens`                                   | Account takeover.                                                                                                |
| **Personal access tokens** (`fin_pat_…`, read / write scope)                                                           | Hash in `personal_access_tokens`; plain value in the MCP client config on the owner's laptop                            | Long-lived bearer credential, outside the browser's protections (no SameSite, no httpOnly).                      |
| **Server secrets**: `JWT_SECRET`, `POSTGRES_PASSWORD`, SMTP password, Cloudflare DNS token (infra), GHCR / deploy keys | `/srv/finances/.env` (mode 600), container environments, GitHub Actions secrets                                         | `JWT_SECRET` forges any session; the DB password reads everything.                                               |
| **Backups**                                                                                                            | restic repository off-site (infra repo)                                                                                 | A full copy of the database, outside the tailnet.                                                                |
| **Bank exports** waiting to be imported                                                                                | The owner's devices; git-ignored `data/` in a dev checkout; never on the server except in the request body of a preview | Raw statements (account numbers, names).                                                                         |
| **Availability**                                                                                                       | The VPS                                                                                                                 | Low: the app is read once a month and nothing depends on it in real time.                                        |

## 2. Actors

| Actor                                                                                             | Capabilities assumed                                                                                                                                                                                                                                            | In scope |
| ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| **A1. Internet attacker**                                                                         | Reaches the VPS public IP only. ufw and the Hostinger firewall drop all inbound traffic; DNS records point at the tailnet IP.                                                                                                                                   | Yes      |
| **A2. Device on the tailnet**                                                                     | Any device the owner enrolled (laptop, phone), possibly compromised by malware or a malicious browser extension. Reaches Caddy on 443 per the Tailscale ACLs.                                                                                                   | Yes      |
| **A3. Malicious web page visited by the owner** while their phone or laptop is on the tailnet     | Runs JavaScript in the owner's browser on another origin; can send cross-site requests to `finances.<base>` (which resolves to a reachable tailnet IP) and frame it. A page on a **sibling subdomain** of `<base>` (the portal, a future app) is **same-site**. | Yes      |
| **A4. Stolen or borrowed phone**                                                                  | Unlocked, or locked with the installed PWA holding a 30-day refresh cookie.                                                                                                                                                                                     | Yes      |
| **A5. Malicious imported file**                                                                   | A bank or exchange export crafted to break the parser, exhaust memory, or carry a payload into the UI or a later export. **Transaction labels are partly third-party controlled**: a SEPA transfer reference or a merchant name is written by someone else.     | Yes      |
| **A6. Compromised dependency** (npm package, base image, GitHub Action)                           | Code running inside the API, web or CI with their privileges; can read env secrets and exfiltrate over the network.                                                                                                                                             | Yes      |
| **A7. Compromised or curious third-party service**: CoinGecko, Esplora / JSON-RPC endpoints, SMTP | Sees what the server sends it; returns arbitrary responses (oversized, malformed, redirects).                                                                                                                                                                   | Yes      |

Neighbour container** on the shared `proxy` Docker network (another app behind Caddy)       | Reaches `finances-web:3000` directly, bypassing Caddy; inside the private ranges that `TRUSTED_PROXIES` trusts.                                                                                                                                                 | Yes      |
| **A9. Future public MCP endpoint** (#78, OAuth)                                                   | Anyone on the internet once #78 opens a public route; today only the local stdio MCP server exists.                                                                                                                                                             | Planned  |
| Hostinger, Tailscale, Cloudflare, GitHub themselves; physical and social-engineering attacks      | —                                                                                                                                                                                                                                                               | No       |

## 3. Trust boundaries and data flows

```
 owner's browser / PWA ──TLS──▶ Caddy (infra, :443 on the tailnet IP, HSTS, nosniff, Referrer-Policy)
      │  (B1: tailnet + TLS)          │ reverse_proxy, sets X-Forwarded-For
      │                               ▼
      │                     web (TanStack Start SSR, Nitro)  ◀── proxy network (B2: shared with other apps)
      │                       │ /api/* proxy: rebuilds X-Forwarded-For, forwards cookies / Authorization
      │                       │ SSR loaders: call the API with the page's cookies, refresh deduplicated
      │                       ▼
      │                     api (NestJS / Fastify)  ── project network only (B3)
      │                       │ Drizzle (parameterised SQL)
      │                       ▼
      │                     db (Postgres 17, volume db_data)  (B4)
      │
 local MCP server (owner's laptop) ──Bearer fin_pat_…──▶ Caddy → web → api      (B5: token, not cookie)

 api ──HTTPS──▶ CoinGecko (asset ids, search text)          (B6: outbound, opt-out)
 api ──HTTPS──▶ Esplora / EVM JSON-RPC (addresses, token contracts)  (B7: outbound, opt-in)
 api ──SMTP──▶ mail relay (reset / verification links)       (B8: optional, off in production)
 GitHub Actions ──Tailscale (tag:ci)──▶ VPS: deploy.sh (pull images from GHCR, migrate, up)  (B9)
 VPS ──restic──▶ off-site object storage (backups)          (B10)
```

| Boundary                    | What crosses it                                    | Controls in place                                                                                                                                                                                                                                |
| --------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| B1 client → Caddy           | Everything                                         | Tailnet only (ACL grants `autogroup:admin` → `tag:server` on 22/80/443), TLS (wildcard cert, DNS-01), HSTS, Caddy logs without query strings or Referer.                                                                                         |
| B2 Caddy / proxy net → web  | Pages, `/api/*`, server functions                  | `TRUSTED_PROXIES` decides whose `X-Forwarded-For` is believed; server functions behind TanStack's CSRF middleware (`Sec-Fetch-Site: same-origin`); `no-store` on every handler response.                                                         |
| B3 web → api                | Cookies, bearer tokens, bodies                     | API not on the proxy network, no published port; API trusts `X-Forwarded-For` only from private ranges; global `JwtGuard` audit (`app.routes.spec.ts`); `ValidationPipe` whitelist; per-IP and per-token throttling; helmet headers; `no-store`. |
| B4 api → db                 | SQL                                                | Drizzle query builder, bound parameters; DB errors stripped of bound values before logging.                                                                                                                                                      |
| B5 MCP → api                | Personal access token                              | SHA-256 stored, scopes, deny-by-default for writes, audit table, own rate-limit bucket.                                                                                                                                                          |
| B6 / B7 api → third parties | Asset ids, search text, addresses, token contracts | Base URLs from env only, path segments URL-encoded, `redirect: 'error'`, timeouts, body length cap, numbers parsed as strings; wallet sync off by default.                                                                                       |
| B9 CI → VPS                 | Images, migrations                                 | Ephemeral `tag:ci` node, SHA-pinned actions, Trivy before push, automatic rollback.                                                                                                                                                              |
| B10 VPS → backup storage    | Database dumps                                     | restic (encrypted client-side); restore test is an owner check (report §5).                                                                                                                                                                      |

## 5. Assumptions to revisit

- **Tailnet only.** Most low findings are low _because_ only enrolled devices reach the app. #78 (public MCP with OAuth) changes that for at least one route: re-run T1, T2, T6, T13 and T14 against the public path, and fix every medium finding of the report first.
- **One app per registrable domain is not the case.** The portal (and any future app) on `<base>` is same-site with Finances: `SameSite=Lax` cookies do not protect against it (T7). Hosting user-controlled content on a sibling subdomain would raise T7.
- **The owner reads exports in a spreadsheet.** T9 assumes the CSV report is opened in Excel / LibreOffice / Numbers.
- **The web process is single-instance** (refresh deduplication). Scaling it out needs the refresh race (T2) fixed in the API.
