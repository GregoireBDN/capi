# Threat model

- **Issue**: #102 (milestone M7 Access & security)
- **Date**: 2026-11-14, on `main` at `5abde73` (after #170, wallet sync). **Revised 2026-11-17** on `main` at `bd67670`: the repository is public, and the remote MCP OAuth server of #78 is merged (shipped disabled); A9–A11, B11–B12 and T19–T22 are new (report §7). **Revised 2026-11-27** for ADR 0009 (several users, planned): A12–A13 and T23–T26 are new.
- **Companions**: [ASVS 4.0 level 2 checklist](asvs-l2-checklist.md), [audit report](audit-2026-11-14.md)

Capi (« Finances » until #464) is a single-user, self-hosted personal finance tracker. One owner, one account, no public sign-up. A few invited users, each seeing only their own data and what they share, are planned (ADR 0009, #538): actors A12–A13 and threats T23–T26 describe them. It runs on one VPS reachable only through the owner's tailnet (ADR 0001) and is used mostly from an iPhone as a PWA, plus a local MCP server for Claude. A remote MCP endpoint for the Claude apps (#78, ADR 0003) is in the code but off (`REMOTE_MCP_ENABLED`); once enabled, its adapter is the one public surface.

**The source is public** (since 2026-11-17): every control below is assumed known to the attacker, including this document, the audit report and the pentest scripts. Nothing relies on the code being secret; what must stay secret is in `.env` files, GitHub secrets and the database.

## 1. Assets

| Asset                                                                                                                                                          | Where it lives                                                                                                                  | Why it matters                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **Financial data**: transactions (labels, amounts, dates), balances, budgets, notes, net worth, crypto holdings                                                | Postgres `db_data` volume; API responses; the browser while a page is open                                                      | The whole point of the app. Confidentiality first (it maps the owner's life, income and habits), then integrity. |
| **Wallet public keys** (xpub / ypub / zpub, EVM addresses)                                                                                                     | `crypto_wallet_keys`; sent to Esplora / JSON-RPC only when wallet sync is on (ADR 0002)                                         | Not spending keys, but an xpub reveals every address, past and future, hence the wallet's history and balance.   |
| **Session**: `__Host-token` (15 min access JWT) and `__Host-refresh_token` (30 days, rotating) cookies                                                         | Browser cookie jar (httpOnly); `refresh_tokens` table (SHA-256 hashes)                                                          | Whoever holds them reads and edits everything except the session-only routes that need a fresh sign-in.          |
| **Credentials**: password hash (bcrypt), passkeys (public keys), password reset and email tokens (hashed)                                                      | `users`, `webauthn_credentials`, `password_reset_tokens`, `email_verification_tokens`                                           | Account takeover.                                                                                                |
| **OAuth grants and tokens** (`fin_oat_` access 15 min, `fin_ort_` refresh 30 days rotated, `fin_oac_` codes 2 min; #78, off by default)                        | SHA-256 hashes in `oauth_tokens` / `oauth_authorization_codes`; plain values only at the Claude connector (Anthropic's servers) | Same reach as a personal access token of the grant's scope, from outside the tailnet once enabled.               |
| **Personal access tokens** (`fin_pat_…`, read / write scope)                                                                                                   | Hash in `personal_access_tokens`; plain value in the MCP client config on the owner's laptop                                    | Long-lived bearer credential, outside the browser's protections (no SameSite, no httpOnly).                      |
| **Server secrets**: `JWT_SECRET`, `POSTGRES_PASSWORD`, SMTP password, Cloudflare DNS token (infra), GHCR / deploy keys                                         | `/srv/capi/.env` (mode 600), container environments, GitHub Actions secrets                                                     | `JWT_SECRET` forges any session; the DB password reads everything.                                               |
| **CI / deploy secrets**: Tailscale OAuth client (`TS_OAUTH_*`, joins the tailnet as `tag:ci`, which may SSH to the VPS as `deploy`), optional `DEPLOY_SSH_KEY` | GitHub Actions secrets (should be `production` environment secrets: F16, #238)                                                  | `deploy` runs Docker on the VPS: root on the server and every app on it.                                         |
| **Backups**                                                                                                                                                    | restic repository off-site (infra repo)                                                                                         | A full copy of the database, outside the tailnet.                                                                |
| **Bank exports** waiting to be imported                                                                                                                        | The owner's devices; git-ignored `data/` in a dev checkout; never on the server except in the request body of a preview         | Raw statements (account numbers, names).                                                                         |
| **Availability**                                                                                                                                               | The VPS                                                                                                                         | Low: the app is read once a month and nothing depends on it in real time.                                        |

## 3. Trust boundaries and data flows

```
 owner's browser / PWA ──TLS──▶ Caddy (infra, :443 on the tailnet IP, HSTS, nosniff, Referrer-Policy)
      │  (B1: tailnet + TLS)          │ reverse_proxy, sets X-Forwarded-For
      │                               ▼
      │                     web (TanStack Start SSR, Nitro)  ◀── proxy network (B2: shared with other apps)
      │                       │ /api/* proxy: rebuilds X-Forwarded-For, forwards cookies / Authorization
      │                       │ SSR loaders: call the API with the page's cookies, refresh deduplicated
      │                       ▼
      │                     api (NestJS / Fastify)  ── project network only (B3)
      │                       │ Drizzle (parameterised SQL)
      │                       ▼
      │                     db (Postgres 17, volume db_data)  (B4)
      │
 local MCP server (owner's laptop) ──Bearer fin_pat_…──▶ Caddy → web → api      (B5: token, not cookie)

 api ──HTTPS──▶ CoinGecko (asset ids, search text)          (B6: outbound, opt-out)
 api ──HTTPS──▶ Esplora / EVM JSON-RPC (addresses, token contracts)  (B7: outbound, opt-in)
 api ──SMTP──▶ mail relay (reset / verification links)       (B8: optional, off in production)
 GitHub Actions ──Tailscale (tag:ci)──▶ VPS: deploy.sh (pull images from GHCR, migrate, up)  (B9)
 public repo / forks ──PRs, issues──▶ GitHub Actions (CI, no secrets for forks)  (B12)

 Claude connector (Anthropic, internet) ──HTTPS──▶ Caddy (public host, planned) ──▶ mcp adapter (apps/mcp --http)
      ──Bearer fin_oat_…──▶ api (/api/oauth/*, /api/*)          (B11: public, OFF until enabled)
 owner's browser (tailnet) ──▶ web /oauth/authorize (consent, fresh sign-in) ──▶ code to claude.ai callback
 VPS ──restic──▶ off-site object storage (backups)          (B10)
```

## 5. Assumptions to revisit

- **Tailnet only.** Most low findings are low _because_ only enrolled devices reach the app. #78 (public MCP with OAuth) changes that for the adapter: T1, T2, T6, T13, T14 and T19 were re-run against it with OAuth on (2026-11-17, report §7) and every medium finding of the earlier passes is fixed. Before enabling it, follow `docs/runbooks/remote-mcp.md` and re-run `stack.sh oauth` on the release.
- **One app per registrable domain is not the case.** The portal (and any future app) on `<base>` is same-site with Finances: `SameSite=Lax` cookies do not protect against it (T7). Hosting user-controlled content on a sibling subdomain would raise T7.
- **The owner reads exports in a spreadsheet.** T9 assumes the CSV report is opened in Excel / LibreOffice / Numbers.
- **The web process is single-instance** (refresh deduplication, a 10 s replay in memory). Since #292 the API also renews a token rotated < 60 s ago again while its successors are unused (a response lost to the network, an iOS suspension or a web restart), so a refresh racing across processes or a deploy no longer burns the family; the window is accepted: a token stolen within it gets a session until the owner's next refresh, which then burns the family (reuse still detected, a little later).
- **The source is public.** Security never relied on obscurity, but the public code now gives every actor the exact routes, limits and checks; the pentest scripts are re-runnable by anyone against their own copy. Keep secrets out of the repository (gitleaks, push protection) and out of logs, and keep findings private until fixed when they are exploitable without write access (`SECURITY.md`).
- **One user.** Every pass so far assumed a single user, so IDOR was checked by code review only (T6). ADR 0009 brings invited users (A12, A13): T23–T26 must pass, through the isolation suite and the multi-user audit (#553), before the first invitation. The owner, as root on the VPS, can still read every user's data; the privacy notice says so (#552).
- **Write access is the trust boundary of CI/CD.** Rulesets protect `main` and tags, the environment protects deploys; secrets must sit behind the environment (#238) for that to hold.
