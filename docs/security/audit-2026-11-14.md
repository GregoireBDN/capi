## 1. Summary

No critical or high finding. Four medium and seven low findings, each filed as a `fix` issue in M7. The access-control model holds up well: every non-public route of the 111 in the OpenAPI document refuses anonymous calls, a `read` token cannot change anything, session-only routes refuse tokens, refresh reuse burns the session family, forged JWTs are refused, the API's error bodies and logs keep data and secrets out (search text aside), the client bundle and the service worker hold nothing sensitive, and rate limits cannot be dodged by spoofing `X-Forwarded-For` through a proxy that doesn't trust the caller.

### F1 — Unbounded body buffering in the `/api` proxy (medium, #173)

`proxyToApi` (`apps/web/src/lib/api-proxy.ts:152`) reads the whole body with `request.arrayBuffer()` before forwarding. The API's limits (1 MB JSON, 5 MB imports) only apply afterwards.

- **Reproduce**: `stack.sh run`, step "anonymous 300 MB body": `web` grows from ~40 MB to ~900 MB for one request, answer 502. Also `04-input.sh`: a 6 MB import gets 502 "API unreachable" through the proxy but 413 straight from the API.
- **Reach**: any device on the tailnet, and any web page the owner opens while on it (`fetch(..., { mode: 'no-cors', method: 'POST', body })` needs no CORS approval). A few parallel requests can exhaust the VPS memory (2 vCPU / 8 GB, shared with other apps).
- **CVSS-like**: AV:N/AC:L/PR:N/UI:R/S:U/C:N/I:N/A:H ≈ 6.5. Availability is a low-value asset here, but an OOM can hit neighbours.
- **Fix**: cap and stream the body (413), forward the API's 413, memory limits on the containers.

### F2 — No CSP or framing protection on pages (medium, #174)

API responses get helmet's strict policy; HTML pages only get `Cache-Control` from the app and HSTS / `nosniff` / `Referrer-Policy` from Caddy (`05-web.sh`).

- **Impact**: no second line of defence if an XSS ever appears in a component rendering labels, notes or names (part of that text comes from third parties, F3); pages can be framed. Cross-site frames carry no session (`SameSite=Lax`), same-site ones (portal, future apps on the base domain) do.
- **CVSS-like**: defence in depth, rated medium because labels are attacker-influenced and the app will gain a public path (#78).
- **Fix**: CSP with hashes / nonces in the global request middleware, `frame-ancestors 'none'`, `X-Frame-Options: DENY`.

### F3 — CSV formula injection (medium, #175)

`cell()` (`apps/web/src/components/month-close/csv.ts:11`) quotes `;`, `"` and newlines but keeps a leading `=`, `+`, `-`, `@`. The report lists the largest one-offs by bank label; a SEPA transfer reference (up to 140 characters) is written by the sender.

- **Reproduce**: import `payload.csv` (`make-fixtures.mjs`, first label `=HYPERLINK(...)`); the label is stored verbatim (`04-input.sh`), as it should be. Flag it one-off, close the month, download the CSV, open it in a spreadsheet.
- **CVSS-like**: AV:N/AC:H/PR:N/UI:R/S:C/C:L/I:L/A:N ≈ 4.7 (needs the owner to open the export; modern spreadsheets warn on external links).
- **Fix**: prefix such cells with `'` in `cell()`.

### F4 — Sensitive actions without step-up (medium, #176)

Only passkey creation checks `auth_time` (`passkeys.service.ts:110`). `POST /api/access-tokens`, `DELETE /api/profile`, `DELETE /api/auth/passkeys/:id` take any session.

- **Impact**: a few minutes with an unlocked phone or laptop (or a future XSS) become lasting access through a `write` token that survives logout and password reset (F5), or the destruction of the account.
- **CVSS-like**: AV:P/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H ≈ 6.4.
- **Fix**: a shared fresh-auth guard on these routes, `ReauthSheet` on the web side.

### F5–F11 (low)

Details, reproduction and fixes are in the issues. In short:

- **F5** (#177): no change-password route, and production has no SMTP, so the password cannot be changed at all; a reset leaves other sessions and tokens alive; older reset links stay valid; minimum length 8 (ASVS asks 12); bcrypt ignores bytes past 72. Login is faster for an unknown email (no bcrypt): informational on a single-user instance.
- **F6** (#178): a session renewed at least monthly never ends; rotation reads then revokes in two statements (a concurrent replay was refused in `02-session.sh`, but the SQL doesn't guarantee it); no list of active sessions; the stateless access JWT survives logout for its 15 minutes.
- **F7** (#179): `05-web.sh` sends a `text/plain` POST and a multipart import preview with `Origin: https://portal.audit.test` / `Sec-Fetch-Site: same-site` and the session cookie: both accepted. Browsers send `Lax` cookies on same-site form posts, so a page on a sibling subdomain can trigger bodiless and multipart writes. JSON DTO routes are safe (a `text/plain` body fails validation), server functions are protected (403 cross-site / same-site / no header). Cookie names lack `__Host-`.
- **F8** (#180): `/api/docs` and `/api/docs-json` answer 200 without credentials, through the web origin.
- **F9** (#181): `GET /api/transactions?q=...` puts the search text in `req.url` and `req.query` of the API's request log line (seen in `docker logs`). Labels, amounts, cookies, tokens and passwords: 0 occurrences after a full run.
- **F10** (#182): `JWT_SECRET` only needs one character in production; `deep.json` (5 000 levels) makes `ValidationPipe` overflow the stack → 500 and an error log, the process survives.
- **F11** (#183): containers run as `node`, without package managers or published ports, but with a writable root FS, default capabilities and no memory limit; `web` believes `X-Forwarded-For` from any private address, so a neighbour container on the shared `proxy` network can choose the client IP for rate limits and logs (`01-auth.sh`, last step); `X-Request-Id` is taken from the client as is.

- **F12** (`04-input.sh`, "2 MB JSON" line; and a 1.1 MB body): the API refuses the body from its `Content-Length` and closes the socket while the proxy is still uploading, `fetch` throws, the proxy's `catch` answers 502. Memory stays flat (6 MB and 300 MB bodies get 413 from the proxy itself, #173 holds). No security impact: a misleading status for a body the app never sends. **Fixed by #201**: the proxy caps every non-multipart body at the API's 1 MiB and answers its 413 itself, and drops `Expect: 100-continue` (curl sends it for bodies over 1 MB; `fetch` refuses it, which also turned a 3 MB import into a 502).
- **F13** (ZAP baseline alert 10024, reproduced in Chromium with JavaScript off): `LoginForm`, `RegisterForm`, `reset-password`, `ChangePasswordCard` render `<form>` without `method`, inputs named by react-hook-form, so a native submission is `GET` to the current URL. The password lands in the browser history (synced) and the address bar; Caddy strips queries from its log and the API logs paths only (#181), so server logs stay clean. CVSS-like AV:L/AC:H/PR:N/UI:R/S:U/C:H/I:N/A:N ≈ 4.7. Fix: `method="post"` and a submit button disabled until hydration. **Fixed by #203.**
- **F14** (ZAP 10063, 90004 on every page): defence in depth; the app uses no powerful browser feature, and passkeys only need `publickey-credentials-*` on its own origin. **Fixed by #204**: COOP / CORP `same-origin` and a `Permissions-Policy` on pages, `offline.html` and the API (CORP on static files), except COOP on the OAuth consent flow.
- **F15** (checklist re-check): the other rows of #175–#179 are now Pass (evidence in the checklist); these two were not part of the fixes. A lost device's session lasts until a password change or its 90-day end; a sibling subdomain could toss a `token` cookie for the parent domain. **Fixed by #217**: the profile lists the active sessions (sign-in method and time, last use, coarse device) and ends one (fresh session; that device is out at its next refresh); in production the cookies are `__Host-token` / `__Host-refresh_token`, and the plain refresh cookie of a session from before is read once more and cleared (one release), so nobody is signed out by the rename.

### Remote MCP OAuth and adapter (#78, `stack.sh oauth`)

The production compose file doesn't pass `REMOTE_MCP_ENABLED` to `api`, so a deployment can't turn it on by `.env` alone. `stack.sh oauth` checks the kill switch, recreates `api` with `REMOTE_MCP_ENABLED=true` and `REMOTE_MCP_PUBLIC_URL=https://finances-mcp.audit.test`, starts the adapter (`apps/mcp --http`, built from this checkout, read-only, no capabilities, no published port) on the project network, and puts `api` back.

- **Kill switch** (6 checks): every `/api/oauth/*` route 404, also through the web proxy; an OAuth-shaped bearer token 401.
- **OAuth on** (75 checks, 0 mismatches): metadata (issuer, S256 only, consent page on the tailnet origin); registration refuses foreign, mixed and lookalike redirect URIs, confidential clients, the implicit grant and form bodies, returns no secret, 5 / min / IP; consent `GET` 401 anonymous, 403 with a personal token, 400 for an unknown client, foreign redirect, no or plain PKCE, `response_type=token`, unknown scope or resource; approve is session only (personal write token, OAuth write token and same-site form post 403), `deny` redirects with `access_denied` and the state; the code goes to the allow-listed callback with `state` and `iss`; a wrong verifier spends the code, a code is bound to client, redirect URI and resource, and replaying a used code revokes its grant; `allowWrite` is ignored for a read request; a read token reads (also through the web proxy) and is refused writes, session-only routes (tokens, grants, sessions), `DELETE /profile`, cookies; `token-info` answers OAuth tokens only; a write grant reaches `TOKEN_MUTATING_ROUTES` (manual transaction 201) but no delete, no personal token, no self-approval, no exchange import; refresh can't widen the scope or change client, rotates, tolerates a 10 s race and revokes the grant on later reuse; token endpoint 20 / min / IP; RFC 7009 revocation; grants listed without secrets and revoked by the session only (tokens dead at once), unknown grant 404; `oauth_audit` keeps method, route pattern and status only.
- **Adapter** (21 checks, 0 mismatches): `/mcp` 401 with `WWW-Authenticate: Bearer resource_metadata=…` anonymous, with a personal token, a session cookie or an unknown token; 200 for `initialize` and `tools/list` with the OAuth token; foreign `Origin` 403; `GET /mcp` 405; `/api/*`, pages, `/oauth/authorize`, `/.env` 404; metadata documents served; form bodies relayed, repeated parameters 400, JSON-only registration 415; bodies over 16 kB (OAuth) and 8 MB (MCP) 413; `Cache-Control: no-store`, `nosniff`. 130 requests from one untrusted peer with a new `X-Forwarded-For` each: 120 per minute in total, then 429 (the header is ignored).
- **Logs**: 0 `fin_oat_`, `fin_ort_`, `fin_oac_`, `fin_pat_`, `code_verifier`, `Bearer`, authorization header occurrences in the API and adapter logs; the API logged one `warn` "OAuth authorization code replayed: grant revoked" (the replay check); the adapter logs method, a fixed route label and the status.
