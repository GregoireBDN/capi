# Imports

Feature details moved out of [`CLAUDE.md`](../../CLAUDE.md) (#422). The domain rules, workflow conventions and architecture there apply here too.

## Undoing a committed import

- **Undoing a committed import** (`DELETE /api/imports/:id`, #371, ADR 0005 R5, `imports/undo/`) deletes the rows it wrote with what was done on them by hand; re-importing the file brings back the bank rows, not the edits. `GET /api/imports/:id` gives a committed import's `undo`: `editedCount`, the rows edited by hand (filed by hand rather than by a rule, kind changed, one-off flag (these three not counted for a spreadsheet history import, whose rows come filed), note, split, correction, prepaid link, a transfer link that neither its rule nor matching would set again), the absorbed rows left out; and `absorbedManualCount`, the manual transactions its rows absorbed by reconciliation, which the undo puts back as manual transactions (`restoredManual` in its answer). The web reads it when « Annuler l’import » is pressed and says it in the confirmation (« 42 opérations … seront supprimées, dont 12 modifiées à la main et 3 rapprochées de vos saisies : ces 3 saisies seront remises comme saisies manuelles. Réimporter le fichier ne rendra pas les modifications. »), the plain sentence when both are 0.

## Reconciliation with manual transactions

- **Reconciliation** (`apps/api/src/imports/reconcile/`): a `new` import row with the same account and amount, booked at most 5 days from a manual transaction, replaces it on commit (one to one, closest first), keeping its category, kind, note (or typed label), one-off flag and split; the preview shows the match. The row keeps what it does not take over in `transactions.absorbed_manual` (the entry's own day, typed label and note, #371), so undoing the import puts the entry back as a manual transaction **on its own day**, with the row's current category, kind, flags, link, split and amount (the corrected day when the row's date was corrected; the note made from the label goes back to being the label), and re-importing the file reconciles it again. Unmatched manual transactions of the file's period (up to 5 days before its end) stay and are flagged for review. The commit re-matches against the manual transactions as they are then.

## Spreadsheet history import (one-shot)

The owner's pre-app history (a Google Sheet, ~3,250 categorized rows since 07/2023) is imported once from its CSV exports with `pnpm --filter @finances/api import:history` (code in `apps/api/src/imports/history/`, entry `apps/api/src/database/import-history.ts`; `node dist/database/import-history.js` where `tsx` is missing).

- **Dry run by default**: everything runs in one DB transaction that is rolled back unless `--commit` is passed. It prints counts only; `--report <path>` writes a detailed JSON report (merchant keys, line numbers, conflicts) and refuses any path inside the repo outside `data/`.
- **Inputs**: `Transactions` tab (`Date,Mois,Compte,Libellé,Montant (€),Catégorie,Groupe,Relevé,Ponctuel`, UTF-8, `,`-separated, `-1 234,56 €` amounts) and optionally the `Soldes` tab (`Fin de mois` + one column per account) → `balance_snapshots` on the last day of each month, upserted on (account, date). Columns are matched by name; bad rows are reported, never fatal.
- **Mapping** (`history/mapping.ts`): sheet category slugs → seeded slugs; a categorized row has its category's kind (#368; a row in `Revenu` filed under an expense category is a refund of it); without a category the kind comes from `Groupe` (`Mouvement` → transfer, `Revenu` → income, `Dépense` → expense). A `Groupe` / category disagreement where one side is a transfer (`transfer_kind_mismatch`) is filed without a category, with `Groupe`'s kind, in review. Unknown/ambiguous slugs (`paypal`, `virement_emis` outside `Mouvement`, ...) get no or a best-effort category and `needsReview = true`. Account codes `CC`/`LA`/`LJ` → Compte courant / Livret A / Livret Jeune (found by name or created, institution CIC); override with `--accounts <file.json>` and `--categories <file.json>`.
- **Dedupe**: same hashes as bank imports (`computeDedupeHashes`, `classifyRows`), so a re-run inserts nothing. Probable duplicates of rows from another source (CIC CSV) are conflicts: counted and **not inserted** unless `--include-conflicts` (then flagged for review). One `imports` row (`source = 'spreadsheet'`) per account that received rows.
- **Rules**: merchants seen ≥ 3 times and ≥ 90 % in one category and kind get a proposed `contains` rule on their merchant key (skipped when an existing rule already covers them or the pattern would also catch rows filed differently); created at the end of the rule order only with `--create-rules`.
