# Categorization

Feature details moved out of [`CLAUDE.md`](../../CLAUDE.md) (#422). The domain rules, workflow conventions and architecture there apply here too.

## Rules and the review queue

- **The order is computed** (#299, `compareRules` in `categories/rules/categorize.ts`): higher `categorization_rules.priority` first (0 by default), then the most specific rule (a regex, then the longer folded pattern, then more account / amount conditions), then the oldest (`position` is the creation order only); the list carries each rule's `rank`. Overlaps are shown, not ordered by hand: `GET /api/categorization-rules/insights` gives each rule's matches over 12 months and the conflicts (two enabled rules matching the same transactions, not filed by hand, with another category or kind), `POST /:id/prefer` (session only) makes a rule win by raising its priority above the other's, and the preview lists the previewed rule's conflicts (MCP `create_rule` and `update_rule` show them; `list_rules`, #531, reads the rules with their matches and conflicts). The web (`components/rules/`) reads rules as sentences grouped by category, edits them in three steps (« Quelles opérations ? » with the live matches of `POST /matches`, « Classer dans » with the category picker, « Vérifier » with the preview; « Avancé » holds regex, account, amount, active and priority; no kind: a rule gives its category's, #368) and applies the rules after every save, with « Annuler ».
- Uncategorized or flagged transactions go to a **review queue**: « À revoir », a filter of Opérations (#322, `?review=true`; `/review` redirects to it with every date, `REVIEW_SEARCH`). Filtered on it, the list's header counts what is left with « Tout valider » once every loaded row has a category, no sum shows, each row to review ends with « Valider » (or « Classer » on narrow pages, opening the editor on the categories), and a row validated or filed leaves the list at once (`leaveReview`, then a refetch), « Annuler » bringing it back. Its count is the badge of « Mouvements » in the sidebar (#393: Opérations is its sub-page), itself a link to the filter. A large debit that may be a yearly fee asks « Prépayé 12 mois ? » there, with a button that declares it (#439, see [recurring](recurring.md)); the second charge of such a fee is flagged for review when its import is committed.

## Categories and seed data

**Seed data**: `pnpm db:seed` runs `apps/api/src/database/seed.ts`. The default categories (English snake_case `slug`, French display `name`, `kind` = group, hex `color`) live in `apps/api/src/categories/default-categories.ts`; `seedDefaultCategories(db, userId)` inserts a user's missing slugs with `ON CONFLICT (user_id, slug) DO NOTHING` (categories are per user since #555: `db:seed` runs it for every user, sign-up for the new one, an instance without users gets none), so it is idempotent and never overwrites a category the user renamed, recoloured or archived; a default category the user deleted is recorded in `deleted_default_categories` and never re-created. Categories are managed from the Catégories page (`/categories`, `CategoriesService`): each has a colour and an icon (#266, `categories.icon`, one of `CATEGORY_ICONS` in `categories/category-icons.ts`, Lucide names mapped once in `@capi/ui` (`components/category-icon.tsx`: `CATEGORY_ICONS`, same keys and order as the API, read by the picker and by `CategoryIcon`, #287); the default categories get theirs from the seed and migration `0027`, and a re-seed gives a default category without an icon its default one, never replacing a chosen one), both chosen from its icon on that page; wherever a category is named the web shows `CategoryIcon` (`icon`, `color`, `size` `sm` in legends and chips / `md` in list rows, `fallback` glyph; the glyph in the colour on a tile at ~14 % of it; on every page since #288, the only way a category is drawn: no colour dot; recurring and forecast items carry `categoryIcon`, the month report's categories `icon`, a report frozen before icons taking the category's current one through `upgradeReport`), chart legends taking it through the series' or slice's `icon`; new ones get a slug generated from the name (default slugs stay reserved), archived ones (`archivedAt`) leave the pickers (`pickableCategories`, `apps/web/src/lib/categories.ts`) but keep their history, and deleting one in use moves its transactions, rules, recurring items and budgets (summed) to a category of the same kind in one transaction. Rules and imports should reference categories by `slug`, never by display name. Where `tsx` is not installed (production image), run the compiled script instead: `node dist/database/seed.js` from `apps/api`.
