# MCP server (`apps/mcp`)

Feature details moved out of [`CLAUDE.md`](../../CLAUDE.md) (#422). The domain rules, workflow conventions and architecture there apply here too.

- **Write tools** (#77, `tools/*-writes.ts`: `add_transaction`, `categorize_transactions`, `mark_one_off`, `set_transaction_note`, `create_rule`, `update_rule` (#531: pattern, category or enabled of one rule, previewed through `POST /categorization-rules/preview` with `ruleId`, only the changed fields sent to `PATCH /categorization-rules/:id`, an edit that would copy another rule refused), `set_budget_targets` (expense targets and planned income, #315; its preview says what the plan leaves to save); `close_months`, #342; `set_invested_amount`, #358 and #360: an investment account's invested base (not an exchange), its preview the invested amount, result and rate now → after; `split_transaction`, #357: parts by category name or slug and euros as text, its preview giving each part's kind (« remboursement de Restaurants », « revenu Remboursements ») and the effect on the month's budget lines, French error when the parts don't add up; undone in the app or by `categorize_transactions`; since #368 `categorize_transactions`, `add_transaction` and `create_rule` take no kind beside a category: `kind` only goes with `"uncategorized"` or no category, a kind other than the category's is a French error before anything is sent): without `confirm: true` they only read and return a preview of exactly what would change (current state of the selection through `GET /transactions?ids=`); with `confirm: true` they re-read and apply only what still differs, so a repeated call changes nothing more (a manual transaction with the same day, amount and account is refused unless `allowDuplicate`), then list what changed with an undo hint. **No delete tools**: undoing a created transaction, rule or new budget line is done in the app. Annotated `readOnlyHint: false`, `destructiveHint: false`.
- **Bank imports** (#103, `tools/import-writes.ts`): `preview_bank_import` uploads a bank CSV (a local `.csv` path ≤ 5 MB sent as is, or text sent as UTF-8 with a BOM) to `POST /imports/preview` (writes no transaction); the API recognises the CIC export, the standard cash format or a saved import profile from the header (#431, [import formats](import-formats.md)), the tool's description carries the standard format (`STANDARD_FORMAT_HELP`) so Claude converts any other statement into it, an unrecognised header becomes « Format non reconnu » with that format, and the preview text names the format read and lists `ignoredColumns`; `commit_bank_import` commits it only with `confirm: true` (conflicts only with `includeConflicts`; an already committed preview is a no-op) and lists the import's review-queue rows with their ids; `list_imports` reads `GET /imports`. Only `POST /imports/preview` and `/imports/:id/commit` are open to `write` tokens (`@TokenAccess('write')`); discarding or undoing an import stays session-only.
- **Closing months** (#342, `tools/month-close-writes.ts`): `close_months` takes `month`, or `allBefore: true` (every past month left open since the first month ever closed, up to the previous Europe/Paris month, from `GET /month-close`; `from` is required when no month was ever closed, so the pre-app history is never reached by default), at most 24 months per call. Without `confirm: true` it previews each month (already closed / to close, the steps still open from `GET /month-close/:month`); with it, it closes the open months oldest first (`POST /month-close/:month/close`, a 409 counts as already closed). No reopen tool: « Bilan du mois › Rouvrir » in the app.
- **« Libre » per account** (#522, `tools/accounts.ts`): `accounts_overview` reads `GET /envelopes?includeArchived=true` to find the accounts holding envelopes, then `GET /accounts/:id/envelopes` for each of them only, and shows the API's figures on its line (« dont 450 € dans des enveloppes · 1 230 € libre », or « il manque 150 € pour couvrir les enveloppes » when the balance is under them), plus the « libre » total of the bank accounts (their balances minus their envelopes) when any envelope holds money; balances and net worth are unchanged.
- **Integrity checks** (#427, `tools/integrity.ts`): `integrity_checks` (read, default the previous month) reads `GET /api/integrity?month=` and lists each check (✓, ✗, « non vérifié » when it failed; « état actuel » for crypto and money owed) with each finding in French, its account and day; nothing is fixed.
- **Skill « Capi »** (#497, [`skills/capi/`](../../skills/capi/SKILL.md)): the methods (month-end review, statement import with the standard CSV format, investments, transactions and shared expenses, a finance review and investor profile, a project's budget then its envelope (created by the owner in the app: envelope writes stay session only), a bank export guide, the whole crypto import) and the standing rules, read by Claude only when a task needs them; tool descriptions say what a tool does and point to it instead of repeating a method (definitions 50,306 → 43,006 characters, the Skill's tool names checked in `src/skill.test.ts`). Written in English (the app's labels quoted in French, replies in the user's language). The prompts send `SKILL.md` and their method's files (`PROMPT_FILES`) for clients without Skills (`src/skill.ts`, read from `skills/capi/` or `dist/skill-capi/`, copied at build), so a method has one source. Install (claude.ai zip, Claude Code `~/.claude/skills`): [`apps/mcp/README.md`](../../apps/mcp/README.md#skill--capi--497).
- **Tool-definition budget** (#529): `src/skill.test.ts` keeps everything `tools/list` sends under **50,000 characters**, the owner's choice: the long descriptions and the shared `confirm` text were slimmed first (43,006 → 41,366, every guard kept: preview without `confirm`, exact amounts as text, read only), then the cap went from 45,000 to 50,000 to leave room for the few new tools of #519's phase 2 (envelopes, rules, subscriptions review). A new tool slims existing descriptions before asking to raise it again; methods stay in the Skill.
- **Prompt** `revue_du_mois` (title « Bilan du mois », `src/prompts.ts`): walks through the month-end review with `month_close_status` (`GET /month-close/:month`), `list_imports`, `integrity_checks` and the import tools, `review_queue`, the write tools and `set_budget_targets` for next month, then `close_months` after the owner agrees to its preview; investment values, ticking steps and reopening stay in the app.
- **Categorization rules** (#531, `tools/rules.ts`): `list_rules` (read: `GET /categorization-rules` and `/insights`) gives the rules by category as sentences, in evaluation order (rank, enabled, id), each one's matches over 12 months and the conflicts (which rule wins), narrowed by `category` to its rules and the conflicts they take part in; `update_rule` (write) changes a rule's pattern, match type, category or enabled, its preview before → after with what re-applying would change and the conflicts, `applyToExisting` like `create_rule`. Deleting, reordering and « Faire gagner cette règle » stay in the app; the Skill reads the rules before proposing one.
- **Money owed** (#359, `tools/owed.ts`, `tools/owed-writes.ts`): `owed_to_me` (read: both lists per person with the net when someone is owed both ways, the offsets to propose (#484), the month's expected repayments; with `contact`, the net, that person's open items with their ids, their offsets and history), `share_expense` (transaction id, contact names, « moitié » / « parts égales » / an amount each as text; preview: each share, the owner's part, the category before → after, what each owes before → after; people who already have that share are skipped) and `link_repayment` (transfer id, optional contact, `"auto"` or item ids with amounts; preview: the items, what stays in the category, owed before → after; refuses past the transfer or an item in French; items already linked to the transfer are skipped). Letting a debt go, unlinking, offsetting (« Compenser ») and changing a share stay in the app. `subscriptions` shows a shared item's share and the owner's part; `search_transactions` shows who owes what on a row.
- **Invested amounts** (#358, #360, #370, #373): `list_investment_accounts` gives every account's invested amount (« investi »), result and rate by the same rule as the app (`GET /investments/summary`), a crypto account's coins of unknown cost by asset (« hors 0,1 BTC sans coût connu ») and its realised gain (« plus-value réalisée … cette année (… en tout) »), then under each crypto account one line per asset (#523, `GET /accounts/:id/holdings`, stored prices only, never `valuate`, `refresh` or a chain read): its exact quantity digit for digit (`frenchQuantity`), value and price (« PAS À JOUR : cours du … » when stale), cost of the coins of known cost, result, the part « sans coût connu », and the quantity per place when held at several (the owner's location labels only); `set_invested_amount` sets the base of a PEA, a life insurance or employee savings (removing it stays in the app; crypto accounts refused: their cost follows their coins, answered in « À préciser » in the app).
- **Transfer links** (#296): `search_transactions` shows a transfer's other account (`→ PEA` / `← PEA`); `savings_and_goals` says where the invested contributions come from and adds « où est allé l'argent » (`GET /investments/flows`) and the coins sent between crypto accounts with their cost (`GET /investments/movements`). Read only: links are set in the app.
- **Envelopes** (#429, ADR 0008): `savings_and_goals` lists the active envelopes (`GET /envelopes`): total, amount per account, what each paid, its due date and the monthly amount needed, or « il manque … » without a due date, and « sous zéro sur un compte » when an undo left one so. Read only: envelopes are managed in the app (every envelope write is session only).
- **The lines of a PEA or a compte-titres** (#413, #414, `tools/position-writes.ts`): `sync_security_positions` (account, `asOf`, every line with its ISIN checked (`src/isin.ts`), name for an ISIN the app does not know, quantity, PRU and price as exact text, the cash) previews through `POST /accounts/:id/positions/statements/:asOf/preview` and writes with `PUT …` only with `confirm: true`; « Rien à modifier » when the statement is already there; no delete tool (a statement is deleted in the app). `list_investment_accounts` lists the lines of each PEA and compte-titres under its row (ISIN, quantity, value and price day, PRU, result, cash); the prompt `importer_mes_investissements` asks for the lines of a PEA's or a compte-titres' « relevé de portefeuille ». `create_investment_account` and `list_investment_accounts` know the `securities` type (« Compte-titres »); dividends are typed in the app only.
- **Investment tools** (#104, `tools/investments.ts`, `tools/investment-writes.ts`, prompt `importer_mes_investissements` in `src/investments-prompt.ts`, setup in [`docs/runbooks/investments-from-drive.md`](../runbooks/investments-from-drive.md)): Claude reads the owner's statements with its own Google Drive connector and writes only the extracted values; the app has no Google credentials and makes no Google call. `list_investment_accounts` (read), `add_investment_snapshots` (`POST /accounts/:id/snapshots/bulk`, new / replaced / unchanged days and the net-worth effect; contributions ride on the snapshots, so there is no contributions tool), `sync_crypto_holdings` (quantities as exact decimal strings, `src/quantity.ts`; owns only the `manual` lines of one location: `import` / `sync` lines are never touched, missing manual lines are set to 0 through `PUT`, never deleted; `POST|PUT /accounts/:id/holdings[/:holdingId]` are `@TokenAccess('write')` for it, and a token may only touch the `manual` lines of a `manual`-source account: `CryptoService.assertTokenMayWrite` answers 403 for exchange / wallet accounts and import / sync lines; the tool refuses those accounts up front) and `create_investment_account` (read only: `POST /accounts` stays session-only, it says what to create in the app).
- **Types** come from `apps/api/openapi.json` via `@hey-api/openapi-ts` (types only) into the git-ignored `src/api/generated/` (`@capi/mcp#generate` depends on `@capi/api#generate`); the fetch client is `src/api/client.ts`, which maps 401/403/409/429/5xx/unreachable to French messages returned as tool errors.
- **Output**: French text, euros formatted from cents at the edge (`src/format.ts`), calendar dates as `dd/mm/yyyy` without time zone conversion, "today" in Europe/Paris; partial months are stated with `periodNote`. Small input schemas (≤ 10 fields), names rather than ids for accounts and categories (`tools/lookup.ts`); transactions are shown with their id, which the write tools take. Amounts typed by the model are parsed from text into cents (`parseEuros`), never through a float.
- **Remote transport** (#78, #328, off by default): `node dist/index.js --http` (`src/http/`) serves `POST /mcp` statelessly (one `McpServer` + `StreamableHTTPServerTransport` per request, JSON responses), the protected resource metadata, and relays the OAuth endpoints to the API (form → JSON). Only `fin_oat_` tokens, checked with `GET /api/oauth/token-info` (cached 30 s) and forwarded to the API; 401 with `resource_metadata`; Origin check, per-IP and per-token limits (`RateLimiter`), client IP from `MCP_TRUSTED_PROXIES` only (IPs, ranges or host names resolved every 30 s like `web`'s, `TrustedProxies` in `src/http/client-ip.ts`); refuses to start unless `REMOTE_MCP_ENABLED=true`. `ToolContext.remote` makes tools avoid the server's disk (`preview_bank_import` refuses `filePath`). In production (#328) it is the `capi-mcp` service (image `ghcr.io/gregoirebdn/capi-mcp` from `apps/mcp/Dockerfile`), started only with the `remote-mcp` compose profile; the `infra` repo serves its seven paths on a public host restricted to Anthropic's range (runbook § 3).
- **Tests**: Vitest with synthetic fixtures through a real MCP client over `InMemoryTransport` and a mocked `fetch` (`src/test/mock-api.ts`); no database.
